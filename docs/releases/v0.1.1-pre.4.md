# XArchive v0.1.1-pre.4

> Pre-release notes generated from the `feat/extraction-aria2-pipeline` development branch on September 18, 2026.
>
> This is a development pre-release. The v1 Sidecar/download path and synchronous `archive_tweet` compatibility path remain in migration. Windows runtime, packaged artifact, WebView2, process-tree, file-lock, Native Host, and real-account validation are not implied by Linux CI success.

## Summary

This pre-release consolidates the Linux-verifiable work from U2 through U6:

- cooperative Sidecar cancellation and shutdown interruption;
- Unix process-group cleanup for Sidecar child trees;
- Sidecar protocol v2 typed contract;
- gallery-dl extraction-only adapter contract;
- aria2-only backend-neutral transfer driver;
- one-shot URL refresh contract for expired media URLs;
- expanded Rust, Python, Node, schema, and fixture validation;
- updated Windows Validation Queue and manual blocked-verification procedures.

## U2 — Cancellation and process lifecycle

- Distinguishes user cancellation (`CANCELLED`) from shutdown/crash interruption (`INTERRUPTED`).
- Sidecar consumes `cancel` and `shutdown` while gallery-dl is running.
- Timeout, cancellation, interruption, and ordinary extraction failures use stable error codes.
- Unix Sidecar supervision creates a dedicated process group and terminates the complete child tree during shutdown/force cleanup.
- Windows process-tree behavior remains a Windows-only validation item; the current Linux implementation does not claim Windows Job Object support.

## U3 — Sidecar protocol v2 contract

- Adds typed `hello`, `extract`, `cancel`, and `shutdown` command models.
- Adds typed `ready`, `extraction_started`, `extracted`, `cancelled`, `failed`, and `log` events.
- Enforces protocol version, request identity, Tweet ID/X URL binding, required capabilities, unknown-field rejection, and v1 rejection.
- Adds Rust/Python models, JSON Schema, JSONL fixtures, and contract tests.

## U4 — Extraction-only gallery-dl adapter

- gallery-dl is constrained to metadata and media discovery; it does not own media transfer.
- Extraction command construction uses `--skip-download` and rejects media-writing flags.
- Media identity is stable across extraction results where metadata identity or URL identity is available.
- Filenames are sanitized to a single safe path component with deterministic fallback names.
- Only the `Referer` and `Accept` request headers are allowlisted.
- Raw metadata and downloaded-file facts are not part of the v2 extraction result.

## U5 — aria2-only transfer driver

- Builds a backend-neutral `MediaTransferPlan` from typed extraction results.
- Uses aria2 as the only transfer backend in the new driver contract.
- Supports multi-GID submission and polling, plan-order completion, monotonic progress checks, timeout, cancel, shutdown, error/removed classification, and partial/`.aria2` cleanup.
- Rejects unsafe filenames, non-HTTP(S) URLs, duplicate media identities, disallowed headers, and header injection.
- The new driver is not yet wired into the Desktop production executor; the old `DownloadRouter` migration path remains present until U7/U8.

## U6 — URL expiry refresh contract

- Classifies 401/403/expired/signature/access-denied transfer failures as refreshable URL failures.
- Performs at most one complete extraction refresh per transfer attempt.
- Rebuilds the transfer plan from the refreshed extraction result.
- Matches the refreshed media collection by stable media identity and filename.
- Returns `EXTRACTION_RESULT_CHANGED` when media identity/filename membership changes.
- Does not refresh for ordinary transfer errors, cancellation, shutdown, timeout, or local filesystem/permission/disk failures.
- Production Desktop/Supervisor wiring and real old-GID/new-GID integration remain U7 work.
