# XArchive v0.2.0-pre.2

> 基于 U10/U11 开发线构建的 Windows x64 预发布版本。本版本用于验证和反馈，不是稳定生产版本。

## 版本范围

- 源代码分支：`feature/u7-desktop-production-integration`
- 应用源代码修订：`077c090f2ad41e82f96f735181e09d14fbc5ebec`
- 发布日期：2026-09-20
- 目标平台：Windows x64

## 主要更新

### Desktop 生产链路接入

- 保留 U8 之后的 Sidecar protocol v2、extraction-only gallery-dl 流程和 aria2-only media transfer 边界。
- Desktop executor 使用 runner-owned execution context，隔离 SQLite、FileStore、Sidecar 和 aria2 生命周期。
- 支持任务提交、状态查询、取消、shutdown、recovery 和 attempt fencing 的生产执行路径。
- 归档提交继续执行媒体身份、文件名、staging 和最终目录安全校验。

### Core Bootstrap 与首次设置

- 新增 Core Bootstrap 状态查询，报告 embedded catalog、active component、缺失组件和诊断信息。
- 首次启动设置向导支持 portable download directory 与系统 `Downloads/XArchive` fallback。
- 设置完成后重新初始化 runtime、database、archive 和 staging 路径。
- 空 embedded catalog 会明确显示等待已验证 release assets，不会伪造组件已安装状态，也不会执行动态网络下载。

### 发布资产契约

- 新增版本化 release asset 命名和 manifest 校验契约。
- manifest 强制要求 release tag、Windows x64 平台、资产 kind、SHA-256、文件大小和许可证条目。
- 禁止使用动态 `latest`、缺失 hash/size/license 或逃逸包目录的许可证路径。
- 发布工作流固定外部依赖版本，减少 release 重建时的内容漂移。

## 发布资产

本 release 预期包含以下四项 Windows x64 资产。实际文件必须以 GitHub Release 页面显示的已上传资产为准：

| 资产 | 内容 | 依赖策略 |
|---|---|---|
| `XArchive-v0.2.0-pre.2-windows-x64.exe` | XArchive 单文件 Desktop 应用 | 仅应用 executable；首次运行按设置向导配置目录 |
| `XArchive-v0.2.0-pre.2-windows-x64.7z` | 仅包含 `xarchive-desktop.exe` 的单文件 7z 包 | 与上项相同，不包含外部组件 |
| `XArchive-v0.2.0-pre.2-windows-x64-full.7z` | `.exe`、Extension、PyInstaller worker、gallery-dl、aria2、manifest、许可证文件 | gallery-dl 和 aria2 从各自官方 release 下载后固定版本组装 |
| `XArchive-v0.2.0-pre.2-windows-x64-repository-dependencies.7z` | 本仓库 Extension、PyInstaller worker、manifest、许可证文件 | 只包含本仓库发布依赖；gallery-dl/aria2 不复制到此包，默认由官方仓库来源提供 |

### 外部依赖来源

- gallery-dl: 官方 `gdl-org/builds` release `2026.09.20`，Windows x64 `gallery-dl_windows.exe`。
- aria2: 官方 `aria2/aria2` release `release-1.37.0`，Windows x64 `aria2-1.37.0-win-64bit-build1.zip` 中的 `aria2c.exe`。
- Extension 与 worker: 当前仓库同一 release source revision 构建/打包。
- 发布 workflow 会在 Windows runner 上运行 `--version`/`--help` smoke check，并将来源与版本写入 bundle manifest。

## 使用建议

1. 一般验证优先使用 `-full.7z`，解压后运行 `xarchive-desktop.exe`。
2. 如果只需要验证 Desktop 启动和设置向导，可使用单文件 `.exe` 或单文件 `.7z`。
3. 如果需要单独加载浏览器 Extension 或复用 worker，使用 `-repository-dependencies.7z`。
4. 首次运行时选择 portable 目录或系统 `Downloads/XArchive`；不要把 `config/`、`cache/`、`download/` 和 `logs/` 提前写入 release archive。

## 已知限制

- 这是 pre-release；Windows WebView2、DPI、键盘焦点、Native Messaging、文件锁、ACL、reparse point、真实 aria2 transfer、gallery-dl extraction 和浏览器集成仍须按 Windows Validation Queue 验证。
- 空 embedded component catalog 仍是有意设计：在真实资产 hash、license、probe 和 activation marker 完成固定前，应用不会自动激活未验证组件。
- 真实 X 登录、Cookie、受限媒体、过期签名 URL 和外部网络服务可能导致归档失败。
- 不提供安装器；本次资产是 portable/standalone 形式。

## 验证记录

- Linux workspace 与 Desktop checks、tests、format、clippy 和 release manifest tests 在发布提交前执行。
- Windows 构建、外部组件下载、资产 smoke、7z 内容和 release upload 以对应 GitHub Actions run 为准。
- `FAIL`、`BLOCKED` 或 `NOT RUN` 的 Windows 项目不会被本 notes 视为 PASS。
