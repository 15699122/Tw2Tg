# XArchive v0.2.0-pre.14（发布链路演练）

> **这是一个未产生产物的预发布演练，不是可用性发布。** 本次演练用于验证 Windows 发布就绪门的直连 msedgedriver capability 修复。`v0.2.0-pre.13` 在 Windows 就绪门因直连模式仍发送非法顶层 `webviewOptions` 而失败；本版本移除该 capability，改为仅发送 `browserName: webview2` 与 `ms:edgeOptions.binary`。

## 使用范围与限制

- 本项目用于**个人用途**，按现状提供；**不保证在其他设备、账号、网络或浏览器配置下可用**。
- **不承诺真实 X 帖子归档成功。** 真实归档依赖 X 的登录状态、页面结构、限流和网络环境。
- 本演练的资产（如产生）只用于核对发布流程、资产命名、7z 格式、哈希与 release manifest，不代表 Windows 功能、兼容性或人工验收通过。

## 本轮变更

- 修复直连 msedgedriver 模式向 WebDriver 发送非法顶层 `webviewOptions` capability；
- 保留 tauri-service 模式的既有 `webviewOptions` 配置；
- 增加/更新配置回归测试和 Windows WDIO 交接说明；
- Linux 定向回归测试已通过：35/35。

## 实际演练结果（2026-09-29）

| 阶段 | run | 结果 |
|---|---|---|
| Linux Pre-Release | `36568386401` | 成功：创建 tag `v0.2.0-pre.14`，target `5b2bf93` |
| Windows Release Build | `36568849798` | **失败**：`Run final executable UI readiness gate` 在创建 WebDriver session 时报告 `session not created: DevToolsActivePort file doesn't exist`；0 specs，未上传资产 |

诊断显示 pinned `msedgedriver 153.0.4234.48` 已在 4445 正常监听，WebView2 Runtime 与 driver 版本一致，应用进程可存活 10 秒；失败发生在 WebView2 session 创建阶段。该结果与既有 Windows batch-4 的 `BLOCKED_AUTOMATION` 证据一致，不能归因于 Dashboard 或应用渲染缺陷，也不能据此标记 Windows UI readiness PASS。GitHub Release 记录已删除，tag 保留为历史锚点。

## 发布源码与验证边界

- 预发布 tag：`v0.2.0-pre.14`，由 `Linux Pre-Release` workflow 在 `release/v0.2.0` 的提交 `5b2bf93` 上创建；
- Windows workflow 必须验证 tag 与 checked-out source parity 后才允许上传资产；
- Windows 本机验证队列仍保持 `PENDING`，不得将 hosted-runner readiness gate 成功扩大为完整 Windows 验收；
- 若演练失败或没有资产，应保留 workflow run 与诊断 artifact，并将该版本标记为不可用，不向 tag 补传未经验证的资产；本轮 Windows 队列保持 `WINDOWS_VERIFICATION_PENDING`，WebDriver 项保持 `BLOCKED_AUTOMATION`。
