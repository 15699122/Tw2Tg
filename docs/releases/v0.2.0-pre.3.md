# XArchive v0.2.0-pre.3

> U12–U14 development pre-release. This release contains the latest Linux-verified Native Host/Extension installation contracts, Offline Bundle manifest contracts, and full Linux verification results. Windows-specific runtime and browser validation remains a separate validation phase.

## Release scope

- Source branch: `feature/u7-desktop-production-integration`
- Release source revision: recorded by the Git tag and GitHub Release target
- Release date: 2026-09-20
- Target platform: Windows x64 release assets with Linux-verified source contracts
- Release type: pre-release for validation and integration feedback

## Highlights

### U12 — Native Host / Extension installation flow

- Fixed Native Messaging Host name: `com.tw2tg.xarchive`.
- Added a pure Node installation contract for MV3 Extension and Native Host packaging.
- Validates:
  - MV3 manifest;
  - `nativeMessaging` and `storage` permissions;
  - X/Twitter host permissions;
  - `src/background.js` service worker;
  - `src/content.js` content script;
  - versioned Extension metadata;
  - 32-character lowercase Chrome Extension ID;
  - Native Messaging `allowed_origins`;
  - Windows x64 installation layout.
- Desktop Extension status now distinguishes file readiness from browser and Native Host connectivity:
  - missing files;
  - browser not loaded;
  - Native Host not registered;
  - Native Host unavailable;
  - disconnected;
  - connected.
- File existence is no longer treated as proof that the browser Extension is connected.

### U13 — Offline Bundle contract

- Added an Offline Bundle manifest contract for the six expected components:
  - Desktop;
  - XArchive worker;
  - Native Host;
  - Extension;
  - gallery-dl;
  - aria2.
- Validates:
  - versioned release tag;
  - Windows x64 platform;
  - relative paths;
  - path traversal rejection;
  - component uniqueness and completeness;
  - SHA-256;
  - file size;
  - required files;
  - license files;
  - Release manifest parity;
  - embedded catalog parity;
  - catalog version parity.
- Explicitly excludes runtime-created directories from the bundle:
  - `config/`;
  - `cache/`;
  - `download/`;
  - `logs/`.
- The Linux implementation does not fabricate Windows binaries, signatures, component hashes, or catalog entries.

### Dependency source policy

- gallery-dl is obtained from its official release source.
- aria2 is obtained from the official aria2 release source.
- Extension, Native Host and XArchive worker are repository-owned release dependencies.
- The bundle must include fixed versions, hashes, sizes, required files and license/source information before it can be treated as a verified Offline Bundle.
- Dynamic `latest` resolution is not part of the release contract.

Actual asset availability and hashes must be confirmed from the GitHub Release asset list and successful Windows workflow run. Release Notes do not convert expected assets into validation evidence.

## Known limitations and validation boundaries

The following items are not closed by Linux verification:

- Windows Tauri/MSVC build and runtime;
- WebView2 behavior;
- Windows Registry and Native Messaging Host registration;
- Windows Named Pipe and ACL behavior;
- Edge/Chrome developer-mode loading and Service Worker reload;
- Native Host reconnect and browser integration;
- Windows process-tree/Job Object behavior;
- aria2c.exe runtime and real multi-GID transfer;
- real gallery-dl extraction and signed URL refresh;
- Windows file locks, junctions, reparse points and cross-volume rename;
- Offline Bundle extraction and startup;
- Authenticode/signature validation;
- SHA256SUMS and license/SBOM scanning;
- real X account, Cookie and external service integration.

These items remain in `docs/validation/windows-queue.md` as `WINDOWS_VERIFICATION_PENDING`, `WINDOWS_BLOCKED`, `BLOCKED_AUTOMATION` or `NOT RUN` with manual procedures.

## Installation and usage guidance

1. Use the standalone `.exe` or executable-only `.7z` for Desktop startup and setup validation.
2. Use the `-full.7z` package for component assembly and Offline Bundle validation.
3. Use the `-repository-dependencies.7z` package when testing the repository-owned Extension and worker dependencies separately.
4. Do not pre-create `config/`, `cache/`, `download/` or `logs/` inside a release archive.
5. Do not treat Extension files being present as proof of browser connectivity; load the Extension and register the Native Host explicitly on Windows.

## Verification and reporting rules

- Linux PASS results apply only to the tested Linux working tree and contract scope.
- Windows-only items must be validated on the final tagged revision.
- BLOCKED and NOT RUN items must retain their reason and manual steps.
- No Windows item is considered PASS solely because a Linux test, manifest test or GitHub upload succeeded.
