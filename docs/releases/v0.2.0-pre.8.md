# XArchive v0.2.0-pre.8

> Windows UI 启动诊断与发布门禁修复预发布版本。本版本用于开发和验证，不是稳定生产版本。Windows 最终 artifact 的 startup readiness、真实浏览器集成、Registry、Named Pipe 和完整 runtime 验收仍需以本版本对应的 GitHub Actions/Windows 验证结果为准。

## 版本摘要

本版本基于 `v0.2.0-pre.7`，重点修复 Windows 发布版启动后白屏问题，并将发布前 UI 可用性检查纳入 Windows release workflow。

Windows 上一轮验证已经确认：窗口、WebView、前端入口和 React 能够启动，旧 artifact 的实际错误为：

```text
extensionBusy is not defined
```

该错误来自 `Sidebar` 未接收父组件传入的 `extensionBusy` prop，导致 App shell 在渲染阶段进入 ErrorBoundary。本版本已修复该问题。

随后 Windows ordinary、advanced 和 Full-package artifact 均能显示 Dashboard；但旧诊断版本的 startup marker 又暴露出状态竞态：异步 IPC 阶段覆盖了 `react_mount_completed`。本版本已将 initial IPC 改为只记录诊断事件，不再覆盖最终 React readiness marker。

## 主要更新

### Desktop frontend startup diagnostics

- 新增 frontend bootstrap 阶段标记：
  - `document_loaded`
  - `entry_module_evaluated`
  - `react_mount_started`
  - `react_mount_completed`
  - `initial_ipc_started`
  - `initial_ipc_settled`
- 捕获全局 `error` 和 `unhandledrejection`；
- 提供不依赖 React 的 HTML startup fallback；
- 资源加载失败和启动超时不再表现为无提示纯白屏；
- 增加 root-level ErrorBoundary，继续保留页面级 ErrorBoundary；
- 通过受限 `log_frontend_event` command 将前端诊断写入应用日志。

### Windows white-screen fixes

- 修复 `Sidebar` 的 `extensionBusy` parent/child prop contract；
- 修复 initial IPC 异步阶段覆盖最终 readiness marker 的竞态；
- Dashboard readiness 继续要求真实 `react_mount_completed`，没有通过降低断言或延长等待时间规避问题；
- native WDIO 失败时记录 URL、readyState、root、startup marker、fallback 内容和 screenshot。

### Production asset and release validation

- 增加 production `dist` JS/CSS asset contract tests；
- 检查 production bundle 不包含 WDIO guest 注入；
- Windows release workflow 在资产归档和 GitHub Release 上传前执行最终 `.exe` UI readiness gate；
- readiness gate 失败时停止后续 release asset 上传，并保留诊断 artifact；
- Release manifest 继续校验 source SHA、资产 hash、size、license metadata 和 Extension ID parity。

## GitHub Actions Windows 发布流程

本版本通过 tag push 触发：

```text
v0.2.0-pre.8
```

Windows workflow 应执行：

1. tag/source parity 检查；
2. Rust workspace check/test；
3. Windows Tauri executable build；
4. Native Host build 和 Extension identity 校验；
5. PyInstaller worker build/smoke；
6. gallery-dl 与 aria2 外部依赖下载和版本检查；
7. 最终 executable UI readiness gate；
8. application-only、repository-dependencies、Full 和 Extension 资产组装；
9. release manifest 与 `SHA256SUMS` 校验；
10. GitHub Actions artifact 和 GitHub Release 上传。

只有最终 `.exe` 通过 UI readiness gate 后，后续资产上传步骤才允许执行。

## Windows 验证状态与限制

以下项目必须以 `v0.2.0-pre.8` 对应的 Windows artifact 和 Actions run 结果为准：

- ordinary native WDIO startup readiness；
- advanced WDIO startup readiness 和 plugin checks；
- Full-package executable startup parity；
- `react_mount_completed` 最终 marker 稳定性；
- frontend diagnostic log、WebView2/driver stderr 和 cleanup；
- 最终 release `.exe`、Full bundle 和上传前 readiness gate。

以下项目仍未因本版本 Linux 修复而自动完成：

- Edge/Chrome developer-mode Extension load；
- HKCU Native Messaging Host Registry install/repair/unregister；
- Windows Named Pipe Desktop transport；
- Native Host reconnect、Service Worker reload 和真实 `query_status`/`archive_request`；
- aria2、真实 signed media、filesystem lock/reparse、restart/recovery；
- Offline Bundle 的真实签名、catalog、hash、license 和 parity acceptance；
- installer、updater、Tray、Autostart、Credential Manager 和真实账号链路。

这些项目继续保持 `WINDOWS_VERIFICATION_PENDING`、`WINDOWS_BLOCKED` 或 `NOT RUN`，不得从 Linux 测试或 local package contract 推导为 Windows PASS。
