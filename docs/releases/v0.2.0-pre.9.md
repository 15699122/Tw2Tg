# XArchive v0.2.0-pre.9

> Windows WebDriver 驱动探测修复、固定工具链与发布门禁诊断预发布版本。本版本用于开发和验证，不是稳定生产版本。Windows 最终 artifact 的 native WebView2 session、真实浏览器集成、Registry、Named Pipe 和完整 runtime 验收仍需以本版本对应的 GitHub Actions 结果与 Windows 验证记录为准。

## 版本摘要

本版本基于 `v0.2.0-pre.8`，修复导致 pre.8 发布门禁失败的真实测试基础设施根因，并把 Windows WebDriver 工具链固定、启动 readiness 诊断和发布门禁接线写成 Linux 可回归的契约。

关键事实链：

1. `v0.2.0-pre.8` 的 Windows Actions run `35593193897` 已在 Tauri、Native Host、worker、外部依赖等步骤通过，但最终 `.exe` readiness gate 在创建 WebDriver session 时失败：

   ```text
   WebDriverError: session not created: DevToolsActivePort file doesn't exist
   ```

   该 run 未进入 Dashboard spec，未生成和上传任何 release asset；

2. 同一时期 Windows 实机诊断确认：把已安装 `@wdio/tauri-service@1.4.0` 的 Edge driver 版本探测手工纠正后，ordinary 与 advanced 二进制都能创建 session 并原生渲染 Dashboard，说明 pre.7 白屏是已修复的产品缺陷，而不是本轮阻塞点；

3. 根因是 service 的 driver 探测正则：`findMsEdgeDriver` 只接受 `MSEdgeDriver x.y`，而当前 Microsoft Edge WebDriver 输出 `Microsoft Edge WebDriver x.y`，于是 service 报 `Driver: unknown` 并且无法进入 session。

本版本用可复现、幂等、可回归的方式修复上述第 3 点，并保留原有 UI 断言与生产 capability 不变。

## 主要更新

### WDIO Edge driver banner 兼容补丁

- 新增 `desktop/scripts/patch-wdio-tauri-service.mjs`：把已安装 `@wdio/tauri-service` 中 `dist/esm/index.js` 与 `dist/cjs/index.js` 的 `findMsEdgeDriver` 探测正则由

  ```js
  versionOutput.match(/MSEdgeDriver ([\d.]+)/)
  ```

  扩展为同时接受两种真实 banner：

  ```js
  versionOutput.match(/(?:MSEdgeDriver|Microsoft Edge WebDriver) ([\d.]+)/)
  ```

- 幂等：已打补丁的安装直接跳过，不重复写入；
- 写入后自校验，校验失败以非零退出，不会静默产生半补丁状态；
- 面向未来：service 升级后不再包含该 pattern 时只输出 warning 并跳过，不阻断安装；
- 只改写这一处正则：不修改业务代码、UI 断言、Tauri capability、依赖版本、driver 版本或下载策略；
- 接线为仓库根 `package.json` 的 `postinstall`，并作为 `desktop` 的 `pretest:e2e`、`pretest:e2e:windows`、`pretest:e2e:windows:advanced` 前置 hook，保证干净 `npm ci` 后 E2E 可直接使用；
- 新增 Linux 回归契约 `desktop/test/patch-wdio-tauri-service.test.mjs`（原 pattern 改写、幂等、已补丁识别、缺失 pattern 容忍）与 `desktop/test/edge-driver-banner.test.mjs`（service 接受 legacy banner、preflight 接受双 banner），并扩展 `desktop/test/ui-wiring.test.mjs` 固定 hook wiring 不被移除；
- 新增 `desktop/scripts/edge-driver-banner.mjs` 作为 Linux 可验证的诊断模型。该模型只描述 service 与 preflight 的 banner 契约，不声明 session 可用。

### WebDriver 工具链（固定 tauri-driver + 与运行时匹配的 Edge driver）

- `desktop/wdio.conf.mjs` 默认关闭 driver 自动安装与自动下载：`autoInstallTauriDriver` 仅在 `WDIO_AUTO_INSTALL_TAURI_DRIVER=1` 时启用，`autoDownloadEdgeDriver` 仅在 `WDIO_AUTO_DOWNLOAD_EDGE_DRIVER=1` 时启用；`EDGEDRIVER_VERSION` 作为显式精确 pin 透传；
- Windows release workflow 的 “Prepare WebDriver toolchain” 步骤用 `cargo install tauri-driver --version 2.1.0-alpha.0 --locked` 安装固定版本 `tauri-driver`，并解析运行环境（WebView2 runtime、Edge browser、PATH 上的 `msedgedriver`）后强制以下规则：

  - 必须存在 `msedgedriver.exe`，否则直接失败（不做隐式下载）；
  - 未显式设置 `EDGEDRIVER_VERSION` 时，要求 `msedgedriver` 的 major 与 WebView2 runtime 的 major 一致；
  - 显式设置 `EDGEDRIVER_VERSION` 时（受控环境精确固定），要求 `msedgedriver` 版本完全等于该值；

- driver 所在目录与固定 `tauri-driver` 目录都会加入 PATH，并把 `tauri-driver` 与 `msedgedriver` 的路径、版本、banner 和 SHA-256 写入 `toolchain.json`，使 driver 来源、版本与 hash 可在 run 中复核；
- 该规则的原因：发布 workflow 之前把 `msedgedriver` 固定为 `EDGEDRIVER_VERSION=152.0.4191.66` 并要求 driver banner 精确包含该版本号，这在任何 hosted 镜像上都不可能成立（`windows-2022` 镜像提供 Edge `152.0.4191.66` + Edge Driver `152.0.4191.77`，`windows-2025`／`windows-latest` 镜像提供 Edge 与 Driver `153.0.4234.32`），并且与 `@wdio/tauri-service` 自身的兼容规则矛盾（运行时派生的 driver 只需 major 相同，只有显式 override 才要求精确相等）。本版本把该检查改为与运行时一致，同时保留无隐式下载与 hash 记录，未放宽任何 UI 断言。

### Windows 启动 readiness 诊断

- 新增 `desktop/scripts/windows-ui-readiness-preflight.ps1`：记录 Windows/Node/Rust/工具链版本、WebView2 与 Edge driver banner 兼容性（`msedgedriver_banner_accepted`、`msedgedriver_banner_reason`）、最终 `.exe` 的直接启动 10 秒进程 smoke、进程与端口快照；
- readiness 步骤在成功与失败路径都收集统一 diagnostics 目录（应用日志、WDIO 日志、test-artifacts、工具链 hash、进程与端口快照）；
- 诊断 artifact 上传改为 `if: always()`，失败时保留证据；
- UI readiness gate 在归档、manifest 与 GitHub Release 上传之前执行，失败即停止后续资产步骤；未通过 gate 的 artifact 不会进入 Release。

## Windows 验证事实与限制

### 已由 Windows 实机确认（受控本地范围）

- `npm ci` 触发根 `postinstall` 后，服务补丁自动生效，**没有**手工修改 `node_modules`；
- ordinary native WDIO：WebDriver session 创建成功，Dashboard spec `3/3` 通过；
- advanced native WDIO：Dashboard `3/3` + plugin `2/2` 通过；
- 退出后无 `xarchive-desktop`、`tauri-driver`、`msedgedriver` 进程以及 `1420/4444/4445/9223` 端口残留（service 上报的残留 driver 由仓库 safety net 回收）；
- 直接启动普通与 WDIO-feature 两个 release 二进制均原生渲染 Dashboard。

因此 `WQ-P1-16` / `WQ-P1-17` 在 **clean-install 本地 v2.0.6 scope** 记为 `WINDOWS_PASS`。

### 仍为 PENDING / FAIL / BLOCKED

- **固定工具链（pinned toolchain）**：`tauri-driver 2.1.0-alpha.0` 安装成功，但 `msedgedriver 152.0.4191.66` 与验证机已安装 Edge `154.0.4258.24` 不兼容，session 在创建前失败：

  ```text
  This version of Microsoft Edge WebDriver only supports Microsoft Edge version 152
  Current browser version is 154.0.4258.24
  ```

  分类为 `BLOCKED_ENV`：`WQ-P1-16` = `WINDOWS_FAIL`（pinned attempt），`WQ-P1-17` = `WINDOWS_BLOCKED`。需要把 pin 对齐到运行环境可用的浏览器/WebView2 版本，或提供受控 Edge 152 runtime。
- **CI/hosted runner**：`v0.2.0-pre.8` run `35593193897` 在 runner 上自动下载了与当时 WebView2 `152.0.4191.66` 匹配的 driver，但 session 仍以 `DevToolsActivePort file doesn't exist` 失败。本版本把 CI 侧的 driver 来源改为"镜像提供 + major 兼容校验 + hash 记录"，去掉了此前那个在任何镜像上都不可能满足的精确版本相等检查，使固定工具链门禁能够真正执行到位。hosted runner 上 WebView2 与镜像 Edge Driver 的实际配对、以及 `DevToolsActivePort` 是否仍阻塞 session，必须以本轮 `v0.2.0-pre.9` run 结果为准；若仍失败，则属于 runner/WebView2 环境问题，不得通过放宽断言或恢复隐式下载来规避。
- **仍未完成**（不得由 Linux 结果推导为 PASS）：

  - Edge/Chrome developer-mode Extension load 与真实 Extension ID 实测；
  - HKCU Native Messaging Host Registry install/repair/unregister；
  - Windows Named Pipe Desktop transport、Native Host reconnect、Service Worker reload 与真实 `query_status`/`archive_request`；
  - aria2、真实 signed media、filesystem lock/reparse、restart/recovery；
  - Offline Bundle 的真实签名、catalog、hash、license 和 parity acceptance；
  - 人工便携首启 setup、权限/跨卷 fallback、日志等级与轮转（`WQ-P1-18` / `WQ-P1-19`）；
  - installer、updater、Tray、Autostart、Credential Manager 和真实账号链路。

### 本版本明确不做的事

- 不降低 `react_mount_completed`、Dashboard `h1` 或稳定区域断言；
- 不通过延长 timeout、增加重试或放宽 capability 来"制造" session；
- 不用进程存活替代 UI readiness；
- 不移动 `v0.2.0-pre.8` tag，也不向 `v0.2.0-pre.8` 上传不同 commit 的资产。

## GitHub Actions 发布流程

本版本通过仓库既有的两个 workflow 发布。

### 1. Linux Pre-Release（`pre-release.yml`）

以 `workflow_dispatch` 运行，输入：

```text
release_tag   = v0.2.0-pre.9
release_title = XArchive v0.2.0-pre.9
source_ref    = feature/u7-desktop-production-integration
```

该 workflow 在 `ubuntu-latest` 上执行 Rust fmt/workspace tests/strict Clippy、Sidecar compile/pytest 和 Node workspace check/test，校验 tag 格式与"tag 尚不存在"，然后用以下命令创建 tag 与 GitHub pre-release，Release 正文取自本文件：

```text
gh release create v0.2.0-pre.9 \
  --target <release source SHA> \
  --title "XArchive v0.2.0-pre.9" \
  --prerelease \
  --notes-file docs/releases/v0.2.0-pre.9.md
```

### 2. Windows Release Build（`windows-release.yml`）

以 `gh workflow run windows-release.yml --ref v0.2.0-pre.9 -f release_tag=v0.2.0-pre.9` 触发（`workflow_dispatch` 必须使用 tag 作为 ref，workflow 会校验 dispatch ref、tag SHA 与 checked-out HEAD 一致）。步骤顺序：

1. tag/source parity 检查；
2. Node `npm ci`、`cargo check` 与 Rust workspace tests；
3. Windows Tauri executable build；
4. Prepare WebDriver toolchain（固定 `tauri-driver 2.1.0-alpha.0`；校验镜像提供的 `msedgedriver` 与 WebView2 的 major 一致；记录路径/版本/SHA-256）；
5. Native Messaging Host build 与 Extension identity 校验；
6. PyInstaller worker build 与 packaged worker v2 contract probe；
7. gallery-dl 与 aria2 外部依赖下载与版本检查；
8. Windows UI readiness preflight（工具链、进程/端口、driver banner 兼容性、最终 `.exe` 10 秒直接启动）；
9. 最终 executable UI readiness gate（ordinary native WDIO）；
10. application-only `.7z`、repository-dependencies `.7z`、Full bundle、Extension ZIP 组装；
11. release manifest 与 `SHA256SUMS` 生成/校验；
12. GitHub Actions artifact 上传与 GitHub Release asset 上传。

只有第 9 步通过后，第 10–12 步才会执行；失败时上传 diagnostics artifact 并停止，**不产生发布资产**。
