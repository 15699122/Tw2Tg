# XArchive v0.2.0-pre.5

> Windows x64 pre-release for UI, Extension status, Native Messaging packaging and integration-contract verification. This is not a stable production release. The release contains Linux-verified implementation changes, while several Windows runtime and browser integration items remain pending or blocked.

## Release summary

This pre-release consolidates the current desktop UI polish, browser Extension state handling, NativeBridge error/reconnect behavior and Windows Native Host packaging contract.

The release is intended for development and validation of:

- the refreshed Dashboard and Settings UI;
- explicit Extension status reporting;
- copyable filesystem paths;
- Native Messaging Host package assembly;
- Windows release workflow and package-boundary checks.

It must not be treated as proof that the complete Windows browser-to-Desktop archive flow is production-ready.

## Highlights

### Desktop UI

- Merged the first-use download-directory explanation into one consistent text block.
- Reduced excess vertical whitespace in the Dashboard setup and runtime sections.
- Adjusted sidebar navigation, Settings spacing and service-status rhythm.
- Reworked Settings sections to use separators rather than repeated outer card borders.
- Fixed the Browser/Globe SVG path so the icon does not lose its upper-right outline.
- Kept focused inner controls such as status boxes, form controls and error panels bordered where those boundaries communicate state or interaction.

### Path interaction

- Unified archive, log, aria2, gallery-dl and Extension paths around the existing copyable-path control.
- Preserved full paths through `title` text while allowing compact display and truncation.
- Kept copy feedback scoped to the individual path control.
- Retained the Tauri clipboard boundary instead of writing directly to the browser clipboard API.

### Extension status

- Separated the actual refresh/checking lifecycle from the resulting Extension state.
- `not_loaded` no longer remains displayed as “检测中…”.
- Added explicit UI mapping for:
  - missing Extension files;
  - Native Host not registered;
  - browser not connected;
  - connected;
  - detection failure;
  - active refresh/checking.
- Added a local Extension refresh action in Settings.

### NativeBridge behavior

- Normalized synchronous `connectNative` failures into rejected Promises.
- Normalized `postMessage` failures.
- Uses `chrome.runtime.lastError` when available during Native Messaging disconnects.
- Rejects pending requests when the Native Host disconnects.
- Clears stale ports so the next request can create a fresh Native Messaging connection.
- Added regression coverage for missing hosts, disconnects and reconnects.

### Windows Native Host packaging

- Full portable packaging now includes the Native Host executable and host manifest boundary.
- Full package assembly requires `XARCHIVE_EXTENSION_ID`.
- Host manifest generation validates the Extension ID and creates the corresponding `allowed_origins` entry.
- The Windows release workflow now builds `xarchive-native-host.exe` and includes Native Host files in the repository-dependencies and Full bundle manifests.
- Core packages remain browser-component-free and do not bundle the Native Host.

## Known limitations

Do not use this pre-release as evidence of:

- a working Edge or Chrome Native Messaging registration;
- a working Windows Named Pipe Desktop transport;
- successful real `query_status` or `archive_request` submission from a browser;
- successful X authentication, Cookie access or real media archiving;
- successful Windows filesystem recovery, reparse-point, ACL or long-path behavior;
- a completed installer, updater, tray, autostart or Credential Manager implementation;
- a complete signed Offline Bundle or final release-asset parity result.

The Windows native render failure remains a separate validation issue. No production UI or Tauri capability change was made solely to guess a fix for that environment-specific failure.

## Package and configuration notes

- Full Windows packaging requires the CI secret `XARCHIVE_EXTENSION_ID` containing the real 32-character lowercase Chrome Extension ID.
- A synthetic Extension ID is acceptable only for local package-contract testing and must not be used for a public release.
- The current workflow produces portable `.exe`/`.7z` scope; it does not create an installer.
- Runtime directories such as `config/`, `cache/`, `download/` and `logs/` are not treated as release-content evidence merely because a package directory exists.
