# XArchive v0.2.0-pre.5

> Windows x64 预发布版本，用于 Desktop UI、Extension 状态、Native Messaging 打包和集成契约验证。本版本不是稳定生产版本。版本包含已在 Linux 验证的实现修改，但多项 Windows 运行时和浏览器集成项目仍处于待验证或阻塞状态。

## 版本摘要

本预发布版本整合了当前 Desktop UI 优化、浏览器 Extension 状态处理、NativeBridge 错误/重连行为和 Windows Native Host 打包契约。

本版本用于以下内容的开发和验证：

- 更新后的 Dashboard 和 Settings UI；
- 显式的 Extension 状态报告；
- 可复制的文件系统路径；
- Native Messaging Host 打包组装；
- Windows release workflow 和包边界检查。

本版本不得视为完整 Windows 浏览器到 Desktop 归档链路已可投产的证明。

## 主要更新

### Desktop UI

- 将首次使用的下载目录说明合并为一段一致的文案；
- 减少 Dashboard 设置区和运行时区多余的垂直空白；
- 调整侧栏导航、Settings 间距和服务状态信息节奏；
- Settings 区块改用分隔线布局，而不是重复的外层卡片边框；
- 修复 Browser/Globe SVG path，使图标不再缺失右上轮廓；
- 状态框、表单控件和错误面板等表达状态或交互边界的内部控件保留边框。

### 路径交互

- 归档、日志、aria2、gallery-dl 和 Extension 路径统一使用既有可复制路径控件；
- 通过 `title` 保留完整路径，同时允许紧凑显示和截断；
- 复制成功反馈只作用于对应的路径控件；
- 继续通过 Tauri clipboard boundary 处理复制，不直接写浏览器 Clipboard API。

### Extension 状态

- 将实际刷新/检测生命周期与最终 Extension 状态分离；
- `not_loaded` 不再一直显示为“检测中…”；
- 增加以下显式 UI 状态映射：
  - Extension 文件缺失；
  - Native Host 未注册；
  - 浏览器未连接；
  - 已连接；
  - 检测失败；
  - 正在刷新/检测。
- Settings 增加 Extension 局部刷新操作。

### NativeBridge 行为

- 同步 `connectNative` 失败统一转换为 rejected Promise；
- 统一处理 `postMessage` 失败；
- Native Messaging 断开时优先使用 `chrome.runtime.lastError`；
- Native Host 断开时拒绝 pending requests；
- 清理失效 port，使下一次请求可以建立新的 Native Messaging 连接；
- 增加 missing host、disconnect 和 reconnect 回归测试。

### Windows Native Host 打包

- Full portable 打包现在包含 Native Host executable 和 host manifest 边界；
- Full 包组装要求 `XARCHIVE_EXTENSION_ID`；
- Host manifest 生成会校验 Extension ID 并生成对应的 `allowed_origins` 条目；
- Windows release workflow 现在会构建 `xarchive-native-host.exe`，并把 Native Host 文件加入 repository-dependencies 和 Full bundle manifest；
- Core 包不包含浏览器组件，也不捆绑 Native Host。

### Windows workflow 实际结果（2026-09-20 后续更新）

Release Notes 编写后，针对 tag `v0.2.0-pre.5`（commit `ea2b8d3afb289239edec29e2e00620870bed2fe6`）执行了一次 Windows Release Build：

| 项目 | 状态 | 证据 | 结果 |
|---|---|---|---|
| Windows Release Build | `FAIL` | run `35507188780` | 失败于 `Build Native Messaging Host` 步骤 |
| 后续 worker/外部依赖/打包/上传步骤 | `NOT RUN` | run `35507188780` | 失败后全部跳过 |
| GitHub Release 资产 | `NOT RUN` | Release asset API | `v0.2.0-pre.5` 资产列表为空（0 个资产） |

失败步骤依赖 CI secret `XARCHIVE_EXTENSION_ID`（Full 包组装要求真实的 32 位小写 Chrome Extension ID），而当前仓库尚未配置该 secret。在该前置修复并重新构建成功之前，`v0.2.0-pre.5` 不能作为包含 Windows 资产的完整发布版本，只能作为 Linux-verified 的开发验证 pre-release。

## 已知限制

不得将本预发布版本作为以下能力的证据：

- 可用的 Edge 或 Chrome Native Messaging 注册；
- 可用的 Windows Named Pipe Desktop transport；
- 从浏览器成功提交真实 `query_status` 或 `archive_request`；
- 成功的 X 认证、Cookie 访问或真实媒体归档；
- 成功的 Windows filesystem recovery、reparse point、ACL 或长路径行为；
- 已完成的 installer、updater、Tray、Autostart 或 Credential Manager 实现；
- 完整的 signed Offline Bundle 或最终 release-asset parity 结果。

Windows native render failure 仍是独立的验证问题。本版本没有为猜测修复该环境相关失败而单独修改生产 UI 或 Tauri capability。

## 打包与配置说明

- Full Windows 打包要求 CI secret `XARCHIVE_EXTENSION_ID`，其值为真实的 32 字符小写 Chrome Extension ID；
- synthetic Extension ID 只能用于本地 package-contract 测试，不得用于公开 Release；
- 当前 workflow 只生成 portable `.exe`/`.7z` 范围，不创建 installer；
- `config/`、`cache/`、`download/`、`logs/` 等运行时目录不会仅因 package 目录存在而被视为发布内容证据。
