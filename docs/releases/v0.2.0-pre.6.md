# XArchive v0.2.0-pre.6

> Browser Extension / Browser protocol hardening pre-release. This is a development and validation release, not a stable production release. The release contains Linux-verified Browser protocol, DOM identity, NativeBridge and page-state implementation changes. Windows browser-to-Desktop integration, Named Pipe, Registry and real browser acceptance remain pending or blocked as documented below.

## Release summary

This pre-release advances the Browser Extension from a basic MV3 content-script/NativeBridge prototype to a more explicit, testable Browser protocol and page integration boundary.

The release includes:

- strict Browser request/response schema handling;
- batch `query_status` responses;
- X Tweet identity and quote/reply extraction hardening;
- NativeBridge timeout, structured error and reconnect-generation handling;
- initial/incremental page status synchronization and DOM-only button state mapping;
- updated Linux regression coverage and Windows validation handoff.

It must not be treated as proof of a complete Windows Edge/Chrome archive flow. Real Browser → Native Host → Desktop transport, Windows Named Pipe, Registry registration and browser acceptance remain outside the Linux evidence in this release.

## Scope and architecture boundary

The current Browser command set remains limited to:

```text
archive_request
query_status
```

`archive_request` returns one `archive_status`. `query_status` returns `archive_status_batch`, with one status entry per requested Tweet ID. Missing jobs use `state = NOT_ARCHIVED` and `job_id = null`.

The Extension does not persist Cookies, signed media URLs, local filesystem paths or media binaries. Page button state is maintained in the DOM only. Windows-specific registration, Named Pipe transport and real browser session behavior are intentionally not claimed as complete.

## Highlights

### Browser protocol and schema

- Added `archive_status_batch` for real batch `query_status` consumption.
- Preserved request ordering so page articles can map status entries by Tweet ID.
- Added `NOT_ARCHIVED` for Tweet IDs without a stored Job instead of returning a whole-batch `NO_JOBS_FOUND` error.
- Added `serde(deny_unknown_fields)` to Browser request, response, Tweet and status models.
- Added the `retryable` field to structured Browser error responses.
- Removed unused duplicate `archive-request.schema.json` and `archive-status.schema.json` definitions; Browser request/response schemas are now the single Browser schema source.
- Synchronized Rust, Native Host, Desktop transport, Extension recognition, Schema and fixtures.

### DOM identity and mutation handling

- Replaced unconditional “first `/status/` link” selection with candidate filtering.
- Separates the primary Tweet permalink from quote-card and reply-context links.
- Prevents `reply_to` from being populated with the current Tweet ID.
- Safely returns no parent ID when the DOM does not expose a reliable reply target.
- Handles quote/reply identity separately.
- Limits MutationObserver work to newly added or affected Tweet articles instead of rescanning the entire page for every mutation.
- Ignores Extension-owned button mutations so injected controls do not create status-query loops.

### NativeBridge and page state

- Added a default 10-second Native Messaging request timeout.
- Cleans pending timers on success, error, disconnect, timeout and `postMessage` failure.
- Rejects duplicate `request_id` values without replacing the original waiter.
- Preserves structured `code`, `request_id` and `retryable` error information.
- Adds port-generation fencing so late messages or disconnects from an old port cannot affect a new connection.
- Adds initial and incremental page `query_status` calls.
- Deduplicates Tweet IDs and splits status requests into protocol-compatible batches of up to 100 IDs.
- Adds DOM-only states: `idle`, `checking`, `submitting`, `queued`, `running`, `complete`, `auth_required`, `failed` and `disconnected`.
- Prevents repeated submission for completed or active Jobs at the page-state boundary.

## Manual validation handoff for blocked Windows items

When Windows automation or prerequisites are unavailable, use the manual steps in `docs/validation/windows-queue.md` and record `WINDOWS_BLOCKED`, `BLOCKED_AUTOMATION` or `NOT RUN` with the exact missing prerequisite. In particular:

1. Load the Extension in Edge and, if available, Chrome developer mode; record the actual Extension ID and Service Worker state.
2. Verify Native Messaging manifest name, executable path, `allowed_origins` and current-user Registry state.
3. Verify `query_status` batching, mixed `COMPLETE`/`QUEUED`/`NOT_ARCHIVED` responses and page button mapping.
4. Verify timeout, duplicate request ID, structured error and old-port fencing using Service Worker DevTools and controlled Host/Desktop interruption.
5. Verify Tweet detail, reply, quote, virtualized timeline, SPA navigation and DOM-node reuse behavior.
6. Verify real `archive_request`/`query_status` forwarding through Native Host and Desktop, including reconnect and Desktop restart.

Do not convert a blocked or unexecuted item to PASS based on Linux unit tests, synthetic Extension IDs or package layout inspection alone.
