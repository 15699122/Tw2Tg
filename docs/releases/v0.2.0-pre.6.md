# XArchive v0.2.0-pre.6

> Browser Extension / Browser protocol hardening 预发布版本。本版本用于开发和验证，不是稳定生产版本。Windows 浏览器到 Desktop 集成、Named Pipe、Registry 和真实浏览器验收仍处于待验证或阻塞状态。

## 版本摘要

本版本将 Browser Extension 从基础 MV3 content script/NativeBridge 原型推进到更明确、更易测试的 Browser protocol 和页面集成边界。

## 主要更新

### Browser protocol 和 Schema

- 新增 `archive_status_batch`，用于批量 `query_status`；
- 没有对应 Job 的 Tweet ID 返回 `NOT_ARCHIVED` 和 `job_id = null`；
- Browser request、response、Tweet 和 status Rust model 拒绝未知字段；
- 结构化 Browser error response 增加 `retryable`；
- 删除未被使用的重复 Browser Schema，保留 Browser request/response schemas 作为唯一 source；
- 同步 Rust、Native Host、Desktop transport、Extension、Schema 和 fixtures。

### DOM identity 和 mutation 处理

- 不再无条件使用第一个 `/status/` link；
- 分离主 Tweet permalink、quote card 和 reply context；
- 防止 `reply_to` 等于当前 Tweet ID；
- 无法可靠识别 parent 时安全返回空值；
- MutationObserver 只处理新增或受影响 article；
- 忽略 Extension 自己插入按钮的 mutation，避免状态查询循环。

### NativeBridge 和页面状态

- 增加默认 10 秒 Native Messaging timeout；
- 清理成功、错误、断开、timeout 和 `postMessage` failure 的 pending timer；
- 拒绝重复 `request_id`；
- 保留结构化 `code`、`request_id`、`retryable`；
- 增加 port-generation fencing；
- 页面初始和增量消费 `query_status`/`archive_status_batch`；
- Tweet ID 去重并按每批最多 100 个 ID 发送；
- 增加 DOM-only 状态：`idle`、`checking`、`submitting`、`queued`、`running`、`complete`、`auth_required`、`failed`、`disconnected`；
- 避免重复提交已完成或正在处理的 Job。

## Windows 状态与限制

本次 Linux 发布准备阶段没有执行 Windows 验证。历史 Windows 结果只适用于其记录的 source revision。

| 项目 | 状态 | 说明 |
|---|---|---|
| Packaged Browser protocol probe | `WINDOWS_VERIFICATION_PENDING` | 需验证 Native Host/Browser framing 和 structured error。 |
| X DOM identity/virtualized timeline | `WINDOWS_VERIFICATION_PENDING` | 需在 Edge/Chrome 和真实或受控 X 页面中验证。 |
| NativeBridge timeout/duplicate/reconnect | `WINDOWS_VERIFICATION_PENDING` | 需验证 Service Worker、Host crash/restart 和 `runtime.lastError`。 |
| 页面 `query_status` 和按钮状态 | `WINDOWS_VERIFICATION_PENDING` | 需验证真实 Browser → Desktop 状态更新。 |
| Named Pipe/Desktop transport | `WINDOWS_VERIFICATION_PENDING` | 不能由 Linux 测试验收 Windows server/ACL。 |
| Native Host Registry lifecycle | `WINDOWS_VERIFICATION_PENDING` / `WINDOWS_BLOCKED` | HKCU install/repair/unregister 需要 Windows Registry。 |
| Edge/Chrome developer-mode load | `WINDOWS_BLOCKED`（除非前置可用） | Linux 未执行真实 Extension ID、Service Worker 和 browser profile。 |
| Windows native WDIO render | `WINDOWS_FAIL`（历史 source scope） | `DevToolsActivePort`/WebView2 session failure 仍为独立问题。 |
| 最终 Windows asset hash/license/parity | `NOT RUN` | 等匹配 Windows workflow 产生资产后验证。 |
| Signed Offline Bundle/installer | `NOT RUN` / `WINDOWS_BLOCKED` | 本版本不声明完成。 |

## 手工验证入口

Windows automation 或前置不可用时，使用 `docs/validation/windows-queue.md` 中的手工步骤，并准确记录 `WINDOWS_BLOCKED`、`BLOCKED_AUTOMATION` 或 `NOT RUN`：

1. 在 Edge 及可用时的 Chrome developer mode 中加载 Extension，记录 Extension ID 和 Service Worker；
2. 检查 Native Messaging manifest、`allowed_origins` 和当前用户 Registry；
3. 验证 `query_status` 分批、混合 Job 状态和按钮映射；
4. 验证 timeout、重复 request ID、structured error、old-port fencing；
5. 验证 Tweet detail、reply、quote、virtualized timeline、SPA navigation 和 DOM-node reuse；
6. 验证真实 `archive_request`/`query_status` forwarding、reconnect 和 Desktop restart。

不得仅凭 Linux unit tests、synthetic Extension ID 或 package layout inspection 将 BLOCKED/NOT RUN 改为 PASS。

## 发布资产边界

- 本版本由 tag `v0.2.0-pre.6` 对应 commit 创建；
- Linux pre-release workflow 负责验证和创建 Release，不生成 Windows executable；
- Windows executable、Native Host、worker 和 portable bundle 只能由匹配 tag/source 的 Windows workflow 生成；
- Windows workflow 失败或不产生资产时，必须在 Release 和验证文档中明确记录；
- 本版本不声明 installer、updater、Tray、Autostart 或 Credential Manager 完成。
