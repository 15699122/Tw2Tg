# XArchive v0.2.0-pre.3

> U12–U14 开发预发布版本。本版本包含最新的 Native Host/Extension 安装契约、Offline Bundle 清单契约以及 Linux 全量验证结果。Windows 专属运行时和浏览器验证仍需单独完成。

## 版本范围

- 源代码分支：`feature/u7-desktop-production-integration`
- 发布源代码修订：由 Git tag 和 GitHub Release target 记录
- 发布日期：2026-09-20
- 目标平台：Windows x64 发布资产及已通过 Linux 验证的源代码契约
- 发布类型：用于验证和集成反馈的预发布版本

## 主要更新

### U12 — Native Host / Extension 安装流程

- 固定 Native Messaging Host 名称：`com.tw2tg.xarchive`。
- 新增纯 Node 的 MV3 Extension 与 Native Host 打包安装契约。
- 校验内容包括：
  - MV3 manifest；
  - `nativeMessaging` 和 `storage` 权限；
  - X/Twitter host permissions；
  - `src/background.js` service worker；
  - `src/content.js` content script；
  - 版本化 Extension metadata；
  - 32 位小写 Chrome Extension ID；
  - Native Messaging `allowed_origins`；
  - Windows x64 安装布局。
- Desktop Extension 状态现在区分文件就绪、浏览器状态和 Native Host 连接状态：
  - 文件缺失；
  - 浏览器未加载；
  - Native Host 未注册；
  - Native Host 不可用；
  - 已断开；
  - 已连接。
- Extension 文件存在不再被误判为浏览器已连接。

### U13 — Offline Bundle 契约

- 新增包含以下六类预期组件的 Offline Bundle 清单契约：
  - Desktop;
  - XArchive worker;
  - Native Host;
  - Extension;
  - gallery-dl;
  - aria2.
- 校验内容包括：
  - 版本化 release tag；
  - Windows x64 平台；
  - 相对路径；
  - 路径穿越拒绝；
  - 组件唯一性和完整性；
  - SHA-256；
  - 文件大小；
  - 必需文件；
  - license 文件；
  - Release manifest parity；
  - embedded catalog parity；
  - catalog version parity。
- 明确排除以下运行时创建目录：
  - `config/`;
  - `cache/`;
  - `download/`;
  - `logs/`.
- Linux 实现不会伪造 Windows 二进制文件、签名、组件 hash 或 catalog 条目。

### U14 — Linux 全量验证

当前工作树（包含 U12/U13 修改）已在 Linux 上完成全量验证：

- Rust workspace 格式化、check、测试和严格 Clippy；
- Desktop Rust 测试：86/86；
- Desktop Node 测试：44/44；
- Extension 测试：7/7；
- Sidecar pytest：21 passed；
- Linux Tauri/WDIO 原生 smoke：2/2；
- Node workspace check 和 build；
- Python compileall；
- `git diff --check`。

验证对象在本次发布提交前曾包含未提交的工作树修改。Windows 验证必须单独使用最终提交或 tag 对应的修订。

### 依赖来源策略

- gallery-dl 从其官方 release 来源获取。
- aria2 从官方 aria2 release 来源获取。
- Extension、Native Host 和 XArchive worker 是本仓库维护的发布依赖。
- Bundle 必须包含固定版本、hash、大小、必需文件以及许可证/来源信息，才能视为已验证 Offline Bundle。
- 动态解析 `latest` 不属于发布契约。

实际资产是否可用以及 hash 必须以 GitHub Release 资产列表和成功的 Windows workflow run 为准。Release Notes 不会把预期资产转换为验证证据。

## 已知限制与验证边界

以下项目不能由 Linux 验证关闭：

- Windows Tauri/MSVC 构建和运行时；
- WebView2 行为；
- Windows Registry 和 Native Messaging Host 注册；
- Windows Named Pipe 和 ACL 行为；
- Edge/Chrome 开发者模式加载和 Service Worker reload；
- Native Host 重连和浏览器集成；
- Windows 进程树/Job Object 行为；
- aria2c.exe 运行时和真实多 GID 传输；
- 真实 gallery-dl extraction 和签名 URL refresh；
- Windows 文件锁、junction、reparse point 和跨卷 rename；
- Offline Bundle 解压和启动；
- Authenticode/签名校验；
- SHA256SUMS 和 license/SBOM 扫描；
- 真实 X 账号、Cookie 和外部服务集成。

这些项目仍按手工步骤记录在 `docs/validation/windows-queue.md`，状态可能为 `WINDOWS_VERIFICATION_PENDING`、`WINDOWS_BLOCKED`、`BLOCKED_AUTOMATION` 或 `NOT RUN`。

## 安装与使用建议

1. 使用单文件 `.exe` 或仅含可执行程序的 `.7z` 进行 Desktop 启动和首次设置验证。
2. 使用 `-full.7z` 进行组件组装和 Offline Bundle 验证。
3. 单独测试本仓库 Extension 和 worker 依赖时使用 `-repository-dependencies.7z`。
4. 不要在 release archive 中预先创建 `config/`、`cache/`、`download/` 或 `logs/`。
5. 不要将 Extension 文件存在视为浏览器已连接；必须在 Windows 上实际加载 Extension 并注册 Native Host。

## 验证与报告规则

- Linux PASS 结果仅适用于已测试的 Linux 工作树和契约范围。
- Windows 专属项目必须在最终 tag 修订上验证。
- BLOCKED 和 NOT RUN 项目必须保留原因和手工步骤。
- 任何 Windows 项目都不能仅因 Linux 测试、manifest 测试或 GitHub 上传成功而视为 PASS。
