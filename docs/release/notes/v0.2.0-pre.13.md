# XArchive v0.2.0-pre.13（发布链路演练）

> **这是一个预发布演练版本，用于核对发布链路与资产形态，不是可用性发布。** 本次演练在 Windows 本机集中验证（见 [`../validation/windows-queue.md`](../../validation/windows-queue.md) 的 R2 轮队列）**尚未执行**的情况下运行；其资产只用于核对发布流程、资产命名、7z 格式、哈希与 release manifest，不作为功能或兼容性结论。前两轮演练的结果：pre.11 在就绪门因 `TAURI_DRIVER_PATH` 导出为目录而失败且未产生资产（见 [`v0.2.0-pre.11.md`](v0.2.0-pre.11.md)）；pre.12 的就绪门改为直连 msedgedriver 后仍在同一门失败，错误为"所有采样到的 window handle 始终停留在空白文档"（tauri-driver 不向 webdriver 9.x 传递应用二进制），同样未产生资产（见 [`v0.2.0-pre.12.md`](v0.2.0-pre.12.md)）。

## 使用范围与限制

- 本项目用于**个人用途**，按现状提供；**不保证在其他设备、账号、网络或浏览器配置下可用**。
- **不承诺真实 X 帖子归档成功。** 真实归档依赖 X 的登录状态、页面结构、限流和网络环境。
- 各资产不做跨设备或完整功能承诺，下表只说明形态与定位。

## 资产清单

| 资产 | 格式 | 形态与定位 |
|---|---|---|
| `XArchive-v0.2.0-pre.13-windows-x64.exe` | `.exe` | 桌面程序本体，可尝试直接启动；不含 Extension、Native Host 与 Sidecar 组件 |
| `XArchive-v0.2.0-pre.13-windows-x64.7z` | `.7z` | 仅包含上面的 `.exe` |
| `XArchive-v0.2.0-pre.13-windows-x64-full.7z` | `.7z` | 含可尝试启动的桌面 `.exe`，以及 Extension、Native Host、Sidecar 等随附组件 |
| `XArchive-v0.2.0-pre.13-windows-x64-repository-dependencies.7z` | `.7z` | 组件/依赖分发包，**不是可直接运行的桌面程序** |
| `XArchive-v0.2.0-pre.13-extension.7z` | `.7z` | 浏览器 Extension 组件分发包，**不是可直接运行的桌面程序**；需先解压再按受控方式加载扩展目录 |
| `XArchive-v0.2.0-pre.13-release-manifest.json` | `.json` | 校验与来源追溯材料 |
| `SHA256SUMS-v0.2.0-pre.13.txt` | `.txt` | 校验与来源追溯材料 |

本版本起**所有压缩包统一为 7z**：Extension 独立包由历史的 `.zip` 改为真实 7z 容器，发布 workflow 使用 `7z a -t7z` 创建并用 `7z x` 验证解包（旧 ZIP 资产名已不在当前发布契约内）。

## 相对 pre.10 的主要变化

- 整合 U7（Popup/Options、批次与认证 WebSocket 通道、七文件发布工具链）与安全分支（R7 审查整改、Windows 打包与 WDIO 配方）为单一基线；
- 版本统一为 `0.2.0`（Cargo workspace、npm、`tauri.conf.json`、Extension manifest/package、侧栏版本显示，并有对齐回归）；
- Extension 发布包由 ZIP 改为 7z；
- 移植到整合基线的安全整改：有界子进程输出读取、错误与日志脱敏、aria2 RPC secret 不进入 argv、归档路径中间链接拒绝、打包输出目录保护、发布文件排除（保留 `.pyd`/`.dll`）、tag 与产物摘要绑定；
- 修复演练暴露的问题（pre.11/pre.12）：CI-only 的 secret 文件测试竞态；Windows 工具链把 `TAURI_DRIVER_PATH` 导出为目录；发布就绪门改用已评审的直连 msedgedriver 配方（自行启动 pinned driver，跳过 tauri-driver），并保留 WDIO 运行输出的证据文件。

## 发布源码

- 预发布 tag：`v0.2.0-pre.13`，由 `Linux Pre-Release` workflow 在分支 `release/v0.2.0` 的 HEAD 上创建；
- Release 资产必须可追溯到该 tag 对应的 commit；Windows workflow 在上传前执行 tag/checked-out HEAD parity 检查，不一致即失败。

## 状态与限制

- 本版本**未**声明真实 X 归档成功、跨设备可用性或完整功能；真实 X 归档尝试不作为发布门禁。
- Windows 本机验证（Full 包构建、三种可启动形态取样、四个 7z 真实格式、Extension 解包加载、直连 msedgedriver E2E、人工项）仍需按 [`../validation/windows-queue.md`](../../validation/windows-queue.md) 执行并回写结果。
- 演练产物只用于核对发布链路；正式 `v0.2.0` 将在 Windows 验证完成后从已验收 commit 单独发布。
