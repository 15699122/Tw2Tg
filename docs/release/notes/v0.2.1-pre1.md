## 3. 本版本变更（相对 `v0.2.0`）

来源区间：`7910033..3cac44e`，外加本发布提交的版本号提升。

### 3.1 界面紧凑化与设置顺序（产品变更）

- **侧边栏 `服务状态` 紧凑化**：收紧 `.sidebar-caption` 下边距、状态行 `min-height`、纵向内边距与行间外边距，保留三列栅格、状态点、标签、状态文本、悬停与 `:focus-visible`，中文标签不裁切。
- **`运行环境` 操作间距恒定**：移除控制面板内「管理组件与设置」链接的 `margin-top: auto`，使状态行、启动/停止按钮与链接按正常文档流排列，不再随任务列表高度拉伸。
- **设置页首段分隔线**：仅移除 `Core Bootstrap` 段落（`#bootstrap-settings`）的顶部分隔线，其余段落分隔线与其 `padding-top` 不变。
- **设置页顺序**：`网络代理`（`ProxySettings`）移到设置页底部，与 `存储位置`、`日志设置` 同属末组。
- **工作台图标区分**：侧边栏 `工作台` 导航项不再复用与 `Sidecar 配置` 相同的波形图标，改为独立的 dashboard 字形。

### 3.2 高清图标资产与运行时窗口图标（产品变更）

图标模糊分两层原因，两层分别处理：

1. **生成层（Linux）**：`desktop/scripts/make-icon.py` 重新生成多尺寸图标资产，避免对低分辨率母图做双线性放大；`desktop/src-tauri/icons/*` 更新为全分辨率资产。
2. **运行时层（Windows 原生）**：`9cc9d5d`（`fix(windows): use high resolution runtime window icon`）修正在 Windows 上运行时窗口图标的选取。根因经 Linux 侧在已安装源码中核对：`tauri-codegen 2.6.3` 的 `CachedIcon::new_ico` 只取 `icon_dir.entries()[0]`，而多尺寸 ICO 的首项是 16 px，因此运行时窗口图标只会用到最小尺寸。该修复属 Windows 原生修改，**只有 Windows 构建能验证**。

> 说明：图标资产修复与运行时图标修复针对**不同层**。二者叠加后的效果、以及各 DPI/Alt+Tab 行为，只有 Windows 能确认（见第 6 节）。

### 3.3 日志页显示过滤器绑定后端有效等级（产品变更）

`c2b754b`（`fix(desktop): bind the logs display filter to the backend effective level`）：日志页「最低等级」下拉的初值改为取自后端有效等级（`AppStatus.logging_level`，由 `LoggingConfig::effective_level()` 产出），而不是写死的 `info`；`main.jsx` 传入该值，`effectiveLevelChanged()` 防止每秒轮询覆盖用户手选的等级。这修复了「渠道默认 `Debug` 但页面显示 `Info`」的不一致。

### 3.4 版本号提升（产品变更）

工作区版本由 `0.2.0` 提升为 `0.2.1`，与目标发布 `v0.2.1` 对齐（沿用 `v0.2.0-preN` 系列的约定：预发布沿用目标正式版本号，不带 `-preN` 后缀）。同步位置：

- `Cargo.toml` `[workspace.package].version`（`Cargo.lock` 随之更新，CI 使用 `--locked`）
- `desktop/src-tauri/tauri.conf.json`
- `package.json`、`desktop/package.json`、`package-lock.json`
- `extension/manifest.json`、`extension/package.json`
- `desktop/src/main.jsx` 的 `app_version` 占位

一致性由 `desktop/test/portable-package.test.mjs` 的 `product version sources stay aligned` 用例强制。

### 3.5 测试与文档

- `28543ed`（`test(desktop): accept Windows line endings in icon assertion`）：使图标生成函数的提取断言容忍 CRLF，不削弱任何断言；首次 Windows 运行在 LF-only 空行模式上对 CRLF 检出失败。该测试改动经 Linux 复核，属 `CROSS_PLATFORM_REVIEW_REQUIRED`，已解除。
- 文档治理：结构化审计 `scripts/docs-audit.mjs`、发布文档合并到 `docs/release/`、外部来源与许可证登记、handoff 只保留当前批次等（见来源区间的 `docs(...)` 提交）。
