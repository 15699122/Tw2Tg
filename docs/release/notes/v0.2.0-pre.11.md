# XArchive v0.2.0-pre.11（发布链路演练，未产生资产）

> **这是一个发布链路演练版本，不是可用性发布；本次演练未产生任何发布资产。** 本文件同时记录演练结果，供后续追溯；演练由 `v0.2.0-pre.12` 取代。

## 演练结果（2026-09-29）

| 阶段 | run | 结果 |
|---|---|---|
| Linux Pre-Release（门禁 + 创建预发布） | `36552938295` | 成功：在 `release/v0.2.0` 上通过 Rust fmt/tests/clippy、Sidecar compileall + pytest、Node check 与 desktop/extension 测试，并创建 tag `v0.2.0-pre.11`（target `46c05b0`）与本预发布 |
| Windows Release Build | `36553596970` | **失败**：在 `Run final executable UI readiness gate` 步骤中断，**未上传任何资产**（发布页资产数为 0） |

首次 Linux 演练（run `36551958362`）还暴露了一个只在 CI 出现的并发测试缺陷：`xarchive-download::tests::removes_secret_file_when_spawn_fails`（exit 101），根因是该测试用进程级临时目录的前后快照判断"spawn 失败无残留"，同二进制的兄弟测试会并发创建同名 secret 文件。已用模块级锁串行化三个相关测试（修复前 12 次 16 线程运行复现 1 次失败，修复后 10/10 通过），并由 `v0.2.0-pre.12` 复跑确认。

Windows 失败根因：

```text
SevereServiceError: Failed to start tauri-driver: tauri-driver [tauri-driver] failed to start:
spawn D:\a\_temp\xarchive-webdriver-tools\tauri-driver\bin ENOENT
```

`Prepare WebDriver toolchain` 步骤把 `cargo install --root` 的目录加入了 `GITHUB_PATH`（正确），但又把同一目录作为 `TAURI_DRIVER_PATH` 导出，而 `@wdio/tauri-service` 会直接 spawn 该值。修复为导出可执行文件路径，并在 `desktop/wdio.conf.mjs` 中把目录型 `TAURI_DRIVER_PATH`/`EDGEDRIVER_PATH` 解析为平台可执行文件（附回归测试），避免同类问题再次以不透明的 `ENOENT` 出现。

## 使用范围与限制

- 本项目用于**个人用途**，按现状提供；**不保证在其他设备、账号、网络或浏览器配置下可用**。
- **不承诺真实 X 帖子归档成功。** 真实归档依赖 X 的登录状态、页面结构、限流和网络环境。
- 各资产不做跨设备或完整功能承诺，下表只说明形态与定位。

## 本次相对 pre.10 的主要变化

- 整合 U7（Popup/Options、批次与认证 WebSocket 通道、七文件发布工具链）与安全分支（R7 审查整改、Windows 打包与 WDIO 配方）为单一基线；
- 版本统一为 `0.2.0`（Cargo workspace、npm、`tauri.conf.json`、Extension manifest/package、侧栏版本显示，并有对齐回归）；
- Extension 发布包由 ZIP 改为 7z；
- 移植到整合基线的安全整改：有界子进程输出读取、错误与日志脱敏、aria2 RPC secret 不进入 argv、归档路径中间链接拒绝、打包输出目录保护、发布文件排除（保留 `.pyd`/`.dll`）、tag 与产物摘要绑定；
- Popup 显示的版本来自 `chrome.runtime.getManifest().version`，不再硬编码。
