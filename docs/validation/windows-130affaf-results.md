Pinned official dependency evidence at 796b027c9361bb407f2a8d9d79c56b2dc4a42ee2:

- `src/types.rs` ProxyConfig distinguishes `pac_url` (explicit configured URL whether or not loaded) from `pac` (first script successfully loaded), and exposes `wpad_dhcp` / `wpad_dns` separately.

The adapter passes false to pac_fallback_must_fail_closed, so its new guard does not reject a DIRECT candidate in this case. WPAD failure states also are not the configured-PAC state currently consulted. Available reports a loaded script, not successful per-URL JS evaluation; do not assume it proves evaluation success.

This is a concrete mismatch in adapter precondition semantics; no actual unproxied packet or Windows controlled PAC FAIL was observed.
